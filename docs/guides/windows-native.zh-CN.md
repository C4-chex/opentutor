# Windows 原生版：本机运行说明

本说明用于已配置的 Windows 原生运行环境。日常使用不需要 Docker Desktop、WSL 或 Redis。源码包不包含运行环境和生成的 EXE；新克隆或新电脑先按仓库 README 的源码启动步骤安装。

## 使用

1. 双击桌面的“OpenTutor 本地学习”，或项目根目录的 `OpenTutor.exe`，会启动服务并自动打开 http://localhost:3001 。启动器有运行状态、停止、备份、日志、缓存清理和托盘入口。EXE 应保留在项目根目录，桌面使用快捷方式。原来的 `Start-OpenTutor.cmd` 仍可使用。
2. 关闭网页不会停止后台服务。用完可以双击 `Stop-OpenTutor.cmd`，释放内存；课程、画像、已提交的学习记录和资料会保留。
3. 重启电脑后再次双击启动即可，不需要重新安装依赖或构建。当前没有配置开机自启。
4. 双击 `Backup-OpenTutor.cmd` 备份。`local-backups/` 下会生成经过完整性检查的 SQLite 备份，以及包含数据库、上传资料和模型设置的 ZIP 完整备份。

模型仍需用户自己的 API Key 和相应网络连接。在设置页面修改模型与学习偏好即可。

## 文件位置

| 内容 | 路径 |
| --- | --- |
| 学习数据库、教学会话、画像、反馈及各项学习记录 | `native-data/data/opentutor.db` |
| 上传及导入文件 | `native-data/uploads/` |
| 原生版模型密钥与运行配置 | `native-data/settings.env` |
| 启动及错误日志 | `native-data/logs/` |
| 进程记录 | `native-data/runtime.json` |
| 项目专用 Python / Node.js | `.runtime/` |
| Python 依赖 | `apps/api/.venv-win/` |
| 本次 Windows Python 依赖版本 | `scripts/requirements-windows.lock` |

这些私有数据及运行目录已加入 Git 忽略。ZIP 完整备份含 API 密钥，请按私人资料保管。未提交的答案草稿仍保存在当前浏览器；换浏览器不会自动带上草稿。

当前配置使用此电脑上的项目绝对路径。先不要随意移动项目文件夹；更换目录或电脑时需重新建立环境并调整 `settings.env` 中的数据库、上传目录路径。完整备份恢复应先停止原生服务，保留原数据副本，再恢复数据库、上传文件和配置。

## 功能与边界

原有资料导入、GitHub 文件预览和选择、课程、AI 教学、学习画像、教学反馈与本地进度继续使用同一套程序及迁移的数据。中文文本使用 UTF-8 模式。

按此前产品要求，编程练习通过粘贴代码与 AI 审阅完成；原生版不在应用中执行用户代码。旧版的容器代码沙箱此前也未就绪，此处显式关闭，不改为在宿主电脑直接运行用户代码。审阅不代表程序已实际运行。

实验功能保持已有开关；当前没有额外开启浏览器自动化或扫描件 OCR，也没有替代尚未开发的教学功能。

服务只监听 `127.0.0.1`，通过当前电脑浏览器访问。EXE 是中文启动与管理入口，Python、Node.js、依赖及数据仍保留在项目目录，不是把整个项目压进一个可随意移动的文件。

## 故障排查

- 启动提示端口占用：先确认旧 Docker 版已停止。脚本不会结束不属于它的进程。
- 页面打不开：查看 `native-data/logs/api-error.log` 和 `web-error.log`。
- 模型请求失败：在设置页检查模型、密钥并测试连接，不需要重新安装项目。
- 修改后端代码后重启服务；修改前端源码后需要重新构建，日常学习不需要。
- 升级 Python 依赖应在项目的 `.venv-win` 中进行，不要修改系统 Anaconda。前端重建时必须使用原生 API 地址 `NEXT_PUBLIC_API_URL=http://127.0.0.1:8000/api`，不能使用 Docker 服务名 `api`。

EXE 源码位于 `scripts/windows/Launcher.cs`，可用 `scripts/build-native-launcher.ps1` 重建。它使用 Windows .NET Framework，不需要额外安装打包器。


## 运行日志保留

服务自行持有日志文件句柄，关闭启动器之后也会继续写入 `native-data/logs/api.log`、`api-error.log`、`web.log` 和 `web-error.log`。

每次重新启动某个服务之前，会将该服务上一轮的两份日志原样移入 `native-data/logs/archive/UTC时间-随机标识-服务名/`，再创建新的当前日志。不会因为“启动”按钮重复点击而归档仍在运行的日志，也不会自动删除旧归档。

EXE 的启动、停止、备份操作另有带 UTC 时间及操作名称的 `launcher-*.log`；成功的周期状态查询不单独留文件。`launcher-error.log` 追加错误，不再覆盖前一条；即使汇总错误文件暂时无法写入，独立操作日志仍保留。完整 ZIP 备份现在同时包含运行日志与归档。

较早版本曾在重启时覆盖同名运行日志，旧版完整备份也不包含日志。这类已被覆盖且没有其他副本的内容无法由新版本补回。对话和教学进度保存在 SQLite，与运行日志分开；不要用删除数据库来处理日志问题。


## 轻量启动与目录结构

日常只需双击桌面的“OpenTutor 本地学习”。启动器采用 Windows 自带的 .NET Framework，直接管理本机服务并打开浏览器；重复双击会唤醒同一个启动器，不会重复启动服务。

- “开始学习”：启动服务，服务就绪后打开网页。
- “检查运行状态”：直接检测本地服务，不额外创建 PowerShell 进程；窗口收起时暂停周期检查。
- “停止学习服务”：释放服务运行内存，保留数据，启动器继续运行。
- “停止并退出”：停止服务并关闭启动器。
- “清理临时缓存”：只删除可再生成的前端构建缓存和指定测试缓存，不删除源码、运行依赖、生产构建、数据库、资料、日志或备份。下次修改前端重新构建时会再次生成构建缓存。

关闭窗口右上角的叉号仍然会收起到托盘。托盘中的“退出启动器（服务继续运行）”只退出管理窗口；需要释放运行内存时使用“停止并退出”。

| 目录 | 职责 | 日常处理 |
| --- | --- | --- |
| `apps/api/`、`apps/web/src/` | 后端、前端核心源码 | 保留，可继续修改与开发 |
| `apps/api/.venv-win/`、`apps/web/node_modules/` | 本机依赖 | 保留，启动时直接复用 |
| `apps/web/.next/` | 网页生产构建 | 保留；仅其中 `cache/` 可清理 |
| `.runtime/` | 项目专用 Python、Node.js | 保留 |
| `native-data/` | 学习资料、画像、记录、模型配置和日志 | 私有数据，保留 |
| `local-backups/` | 学习数据与配置备份 | 保留 |
| `scripts/` | 启动、备份、缓存维护与源码打包工具 | 保留源码 |
| `tests/`、`docs/` | 回归验证与开发说明 | 保留 |
| `source-release/` | 开发检查报告、源码导出与此前归档 | 不参与应用启动；其中可能有私有归档，不整体上传 |

EXE 及桌面快捷方式可重新生成：在项目根目录使用 Windows PowerShell 执行 `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\build-native-launcher.ps1 -DesktopShortcut`。

缓存清理代码位于 `scripts/native-cleanup.py`。不带参数只预览，`--apply` 才执行；维护操作在 `native-control.ps1` 中共用同一套进程与操作互斥逻辑。

知识图谱页面、课程区块和对外图谱接口已移除。旧布局中的图谱区块及解锁建议会在加载时过滤，不影响现有笔记和测验。复习、进度与先修分析共用的数据表保留，不清空历史学习记录。
